# 下载自动重试优化（1.73）

本文保留 1.73 的重试设计与当时验证结果。3.3 源码新增红果指定画质失败后的低清晰度尝试；第三方来源和延迟重试预算不变，取消、磁盘及本地工具错误不触发降级。当前改动与发行状态见 [3.3 说明](release-3.3.md)。

依据用户提供的 Issue #20 截图：下载经常需要人工反复重试，希望自动恢复。

## 行为

- 沿用现有即时恢复机制；仍失败时，红果数字剧集 ID 的临时传输故障最多追加三轮，依次等待 10、30、60 秒。
- 补齐 DNS/断网/连接拒绝等网络错误，以及不完整响应、错误页面、取源等待超时的延迟恢复。
- 结构化取源失败与符合原条件的 HTTP 404/410 保留 3、8、15 分钟等待；两种等待共享三轮预算，不自动降低所选清晰度。
- 下载管理显示“等待重试”、轮次和预计排队时间；与最终失败分开统计。支持立即重试、停止当前任务和全部暂停。
- 批量“重试失败”只处理没有自动计划的失败/停止项；选中后重试、全部开始仍可人工接管计划。
- 保留原有磁盘/权限/安全拦截处理，不把所有失败无条件重试；第三方来源取源策略不变。
- 沿用持久化计划、重启恢复与已完成文件复用。等待恢复不占下载槽位。

## 验证

先添加回归用例，确认旧逻辑在 ENOTFOUND 自动恢复、界面等待状态断言失败，再修改实现。

- `node scripts/check-download-manager.cjs`：13 项通过。覆盖等待状态事件、独立统计、停止与立即重试入口，以及原下载管理回归。
