# 紅果短劇 4.4 預發佈

4.4 是 **預發佈**（`installer-4.4-traditional-pre`）。`windows/4.4-pre-*` 分支的 Windows CI 建置後，由 `publish-release-4-4-pre` 建立發行：安裝版（NSIS）、`.blockmap`、`latest.yml` 與便攜 ZIP。這份發行標成預發佈，**不是** GitHub Latest。已安裝的 4.3 只檢查正式版，不會自動升級到 4.4。4.3（`v4.3`）仍是正式下載。

安裝檔未簽章，SHA256 寫在發行說明。

## 為什麼在線播放會停在「沒有相容的 H.264/HEVC 片源」

畫面上的「本集取源失敗：App：本集暫未提供相容的 H.264/HEVC 片源」只在片源模型已經回來、但每一條流都被編碼篩選拿掉時出現。空回應、裝置註冊失敗、網路中斷是另外的句子。

4.3 已經讓每一次取址用自己的播放裝置，並在背景維持兩台備用裝置。空回應會再換一台裝置、問下一個節點，然後停止。某個節點回了模型、裡面卻沒有可播的 H.264／HEVC 時，4.3 直接停住，沒有用上第二台裝置。同一個編碼在介面上還有幾種寫法（`avc1.64001f`、`h265_hvc1`、`hvc1.1.6…`），App 取源認不出來，也會被當成不相容。

上游裝置註冊仍使用 7.3.9.32。搜尋、目錄與播放各自綁定不同的版本與簽名，這次不改那些版本字串。

## 這次怎麼處理

- App 取源與網頁選流共用同一套編碼家族。H.264 含 `avc`、`avc1` 與 `avc1.` 開頭；HEVC 含 `h265`、`h265_hvc1`、`hvc1`、`hev1`、`bytevc1` 與對應的參數後綴。`bytevc2`、`h266`、`vvc`、`av1` 仍不播。
- 某個節點的模型沒有任何相容流時，再用一台新裝置問下一個節點，只問一次。下一個也沒有，就停，並保留原來的錯誤句子。
- 分集不存在、介面拒絕、位址或金鑰無法解析時，不換裝置。
- 指定清晰度時，第一個節點已有可量測的較低畫質，仍用那一條，不為了再找而多註冊一台。第一個節點沒有可量測尺寸、下一個節點有符合的尺寸，就用符合的那一條，不降級。兩邊都沒有可量測尺寸，就停在「未降級」。
- 備用裝置仍是兩台。每次取址本來就用自己的裝置；這次補上的是「不相容模型」也走既有的換機一次。

## 已知限制

- 兩個節點都只給不相容編碼時，仍會看到同一句取源失敗。
- 整次取址的時間上限仍是 12 秒。第一個節點用掉大部分時間時，第二個節點可能來不及。
- 若所在網路完全連不到片源服務，仍需要到設定啟用代理。
- 安裝檔未簽章。預發佈不會推給已安裝的正式版。
